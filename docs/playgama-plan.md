## 0. 한눈에

- **추천안:** 별도 허브 페이지 `/arcade/`("쉬어가는 게임")에 **6~8개 게임만 큐레이션**해 **클릭해야 로드되는 iframe**으로 넣고, 홈에는 허브로 가는 **작은 카드 하나**만 둔다. 결과 화면 끼워 넣기는 하지 않는다.
- **선행 조건(차단 요소):** 홈의 **Hi5Games 앱테크 배너**가 Playgama 약관 6.1(보상·캐시아웃 플랫폼 링크 금지)에 정면으로 걸린다. Playgama를 켜기 전에 배너를 내려야 한다.
- **모든 Playgama 코드는 설정 파일 하나**(`assets/playgama-config.js`)로 켜고 끈다. clid가 비어 있으면 아무것도 그려지지 않는다.

## 2. Playgama 공식 문서에서 확인한 것

### 2-1. 연동 방식 3가지 [문서]
출처: wiki.playgama.com/playgama/for-partners/getting-started · embed-the-widget · import-the-game-catalog · share-your-referral-game-link

1. **게임 카탈로그 + iframe** — widgets.playgama.com에서 게임을 고르거나 JSON을 내려받는다. JSON의 `gameURL`(예: `https://playgama.com/export/game/popping-candies`)을 iframe `src`로 쓴다. 문서 예시:
   `<iframe src="https://playgama.com/export/game/popping-candies" frameborder="0" width="100%" height="600px"></iframe>` — width/height는 바꿔도 된다고 명시.
   로그인 상태에서 받으면 **clid가 자동으로 붙는다**고 되어 있다. 게임 카드에서 썸네일·아이콘 직접 링크 또는 ZIP을 받을 수 있다.
2. **위젯** — 대시보드에서 위젯을 만들고(장르·크기·색), 세 가지를 붙인다.
   ① `<head>`에 `<script async src="https://widgets.playgama.com/index.js"></script>` (주소 응답 200 확인)
   ② `<body>`에 **위젯마다 다른 초기화 스크립트**(대시보드에서 복사)
   ③ 표시 위치에 `<div id="widget-playgama">` + 안쪽 "Powered by Playgama" 링크
   위젯 너비·높이는 우리가 CSS로 정해야 하고 **게임 최대 높이 320px**. 위젯 ID 형식 예: `WA0000000000000`.
3. **추천(어필리에이트) 링크** — 클릭한 사용자를 **30일 동안 추적**해 Playgama에서 하는 모든 게임 수익을 나눈다.

통계: 대시보드 Statistics 탭, **매일 10:00 UTC 갱신**. iframe(게임별 플레이·광고·인앱 수익), 위젯(노출·클릭·수익), 링크별 통계.

### 2-2. 확인하지 못한 것 [확인 필요]
- iframe `gameURL`에 clid가 **어떤 형태로 붙는지**(쿼리 이름 등) — 문서 예시에는 clid가 없다. 대시보드에서 복사한 실제 코드로만 확인.
- 위젯 스크립트를 `<head>`가 아니라 **클릭 후 늦게 주입해도 정상 동작하는지**, 위젯에서 게임을 누르면 **같은 페이지에서 열리는지 새 창인지**.
- iframe에 `allow="fullscreen"`·`loading` 같은 속성을 더해도 되는지(약관상 '게임 수정'은 아니지만 공식 답이 없음).
- 썸네일을 **우리 서버에 복사해 써도 되는지**, 아니면 Playgama 직접 링크만 써야 하는지.
- 게임이 내려갔을 때 `gameURL`이 어떻게 응답하는지(404? 빈 화면?), 그리고 **삭제를 파트너에게 어떻게 알리는지**(메일? 대시보드?).
- 게임 소개 문구의 **언어 지원 범위**(JSON에 ko/th가 있는지).
- 파트너 FAQ 3개 항목(위젯 게임 바꾸기 / 위젯 광고 종류 등)은 답변이 정적 페이지에 없어 읽지 못했다.
- 약관 6.1의 **"Playgama가 지정한 금지 지역·플랫폼"** 목록.
- Playgama 개인정보처리방침 정확한 URL(사이트 하단 링크 존재, 주소 미확인).

### 2-3. 약관 Chapter 2 (Partners Terms, Last Updated 28.01.2026) 핵심 [문서]
- 2.1 웹 버전만 허용, **네이티브 앱스토어는 서면 승인 필요**.
- 2.4 / 6.1 게임·위젯·문서·브랜딩 **수정·리버스엔지니어링 금지**, 게임 안 브랜딩·링크 제거 금지.
- 3.3 게임이 우리 사이트에서 제대로 돌아가게 할 책임은 파트너에게. 브랜딩 가이드 준수.
- 3.5 Playgama가 게임을 내리면 **요청 즉시 지체 없이 제거**. 라이선스도 즉시 종료.
- 5.1 수익 배분 **Net Revenue의 40%**, 월 단위. 5.3/5.5 **누적 100달러 이상**부터 지급, 미달분은 이월.
- 정의(Invalid Traffic)·5.6·5.7·6.1: 봇·자동 클릭·**사용자 동작 없는 자동 재생**·숨김/보이지 않는 배치·리퍼러 위조·강제 상호작용 금지. 적발 시 수익 몰수·환수·계정 해지.

- 7.4 계약 종료 시 **모든 게임 즉시 제거**.
- 8.1 **수익 데이터와 '협업 사실' 자체가 기밀**(합의 시 예외). 8.5 개인정보보호법 준수는 파트너 책임.

## 4. 배치안

### A. 별도 허브 페이지 `/arcade/` — **추천**
- 6~8개 게임 카드(썸네일 + 한국어 소개 + "▶ 플레이" 버튼). 버튼을 눌러야 그 자리에 iframe이 생긴다.
- 장점: 기존 화면·흐름을 전혀 건드리지 않음. 보상 기능과 물리적으로 분리. 원본 설명을 충분히 넣을 수 있어 SEO·애드센스에 덜 해로움. 켜고 끄기 쉬움.
- 단점: 일부러 찾아와야 해서 초기 유입이 적다 → C로 보완.

### B. 게임 결과 화면 하단 "쉬어가기" 섹션 — 보류
- 장점: 노출이 가장 많다.
- 단점: 결과 화면이 미션·메달·공유와 붙어 있어 3장 #2·#4 충돌. 우리 게임 '한 판 더'를 갉아먹을 위험. 34개 게임 결과 화면에 공통 영역을 추가해야 해 회귀 범위가 큼.

### C. 메인(홈 로비)의 작은 진입점 — A와 함께
- 홈 하단(추천 게임·능력별 선반 아래, '이번 주 나' 위)에 카드 1장 "🎮 쉬어가는 게임 →" → `/arcade/`로 이동만. 홈에서는 **게임을 로드하지 않는다**.
- 운세 탭처럼 "NEW" 점 같은 표시는 넣되, 미션·연속 기록과는 무관.

**추천: A + C.** 4주 측정 후 성과가 좋으면 B를 '보상과 무관한 링크 한 줄'로만 재검토.

### (참고) 위젯 vs iframe
- **iframe(카탈로그) 추천:** 게임을 우리가 고를 수 있고(가족 친화 큐레이션), 클릭 후 로드를 우리가 완전히 통제하며, 게임별 한국어 설명을 붙일 수 있다.
- 위젯은 Playgama가 장르 기준으로 게임을 채우고, 지연 주입·클릭 후 동작이 [확인 필요]. 승인 후 2단계 말미에 선택 실험으로만.

## 5. 페이지 구조 · i18n · SEO

### 5-1. 라우트
```
/arcade/            한국어 허브 (색인 허용, 기능 플래그가 켜졌을 때만 sitemap 포함)
/arcade/en, /arcade/th   2단계 후반 [선택] — 기본은 만들지 않음
```
게임별 개별 페이지는 **만들지 않는다**. 4주 후 상위 1~2개 게임만, 원본 공략이 1,200자 이상 쌓일 때 검토.

### 5-2. 허브 페이지 내용 (얇은 콘텐츠 방지)
- H1 "쉬어가는 게임 — 말로우가 고른 가벼운 웹게임" + 400~600자 소개: 왜 골랐는지, 선정 기준(설치 없음·한 판 3~5분·가족이 함께 해도 되는 장르), 외부 게임이라는 점과 광고·인앱 결제 안내.
- 게임마다 **우리가 직접 쓴 한국어 원본 설명** 150~250자: 한 줄 소개 / 조작법 / 플레이 팁 2~3개 / 이런 분께 추천 / 한 판 예상 시간. Playgama JSON의 설명 문구는 **그대로 붙이지 않는다**(중복 콘텐츠).
- "말로우 두뇌게임과 함께 하기" 링크 블록(우리 게임 중 비슷한 결의 게임 2~3개로 연결 — 사이트 체류는 우리 게임으로 돌린다).
- FAQ 4~5개(FAQPage JSON-LD): 무료인가요·광고가 나오나요·기록이 저장되나요(아니요, 말로우 기록과 무관)·아이가 해도 되나요·게임이 안 열려요.
- `canonical` = 자기 자신. iframe 안 콘텐츠는 우리 콘텐츠로 취급되지 않음을 전제로 설계.

### 5-3. i18n
- 1차는 **한국어 허브만**. 홈 진입 카드도 `CURRENT_LANG==='ko'`일 때만 노출(Hi5 배너와 같은 방식).
- 허브 UI 문구(플레이·불러오는 중·불러오지 못했어요·닫기)는 설정 파일 옆 문구표 `{ko,en,th}`로 관리해 나중에 확장하기 쉽게.
- 게임 소개 문구는 **사람이 쓴 원문만** 쓴다(기계 번역 대량 생성 금지 — 8/23 애드센스 반려 교훈: 얇은 번역판이 '양산 페이지' 인상을 줌). en/th 허브는 원문을 따로 쓸 여력이 생길 때만.

## 6. 성능 설계
- **클릭해야 로드:** 처음엔 썸네일 이미지 + 버튼만. 버튼 클릭 → 그 카드의 영역 안에 `<iframe src=gameURL>`을 넣는다. 페이지 로드 시 playgama.com으로 가는 요청 **0건**(테스트로 강제).
- **CLS 방지:** 카드마다 플레이 영역을 미리 같은 크기로 잡는다(`aspect-ratio`, 모바일 세로는 `height: min(70vh, 600px)`). 썸네일 `<img width height loading="lazy" decoding="async">`.
- **한 번에 한 게임:** 다른 게임을 누르면 이전 iframe을 제거(메모리·소리 겹침 방지). "닫기" 버튼 제공.
- **스크립트:** 우리 로더 `assets/playgama.js`는 `defer`. 위젯을 쓸 경우에만 `widgets.playgama.com/index.js`를 **클릭 후 주입**(동작 여부 [확인 필요]).
- 허브는 서비스워커 네트워크 우선 HTML 그대로. 외부 요청은 SW가 건드리지 않음(`sw.js` 14행 확인).
- 목표: 허브 LCP ≤ 2.5s(모바일), CLS ≤ 0.02, 홈 CLS 현재 수준(0.008) 유지.

### Playgama 대시보드
게임별 gameplays·광고 수익·인앱 수익(매일 10:00 UTC 갱신). 매주 월요일 한 번 표로 옮긴다(수익 데이터는 약관상 기밀 — 문서는 레포 밖 개인 보관 또는 `.gitignore` 경로).

### 매주 비교
- `pg_play_click` 대비 Playgama gameplays 비율 → 0.7~1.3 밖이면 추적 오류 또는 비정상 트래픽 점검.
- **보호 지표:** 우리 게임 세션당 플레이 수, 홈 재방문율, 오늘의 3판 완료율이 시작 전 2주 평균 대비 **10% 넘게 떨어지면** 즉시 C(홈 카드) 끄기.
- 성능: 허브·홈 CLS/LCP 주 1회.

### Go / No-go (4주 차)
- **Go(확장 검토):** 허브 조회 ≥ 300회 **그리고** 조회당 플레이 클릭 ≥ 25% **그리고** 보호 지표 하락 없음 **그리고** 정책 경고 0건. 확장 = 게임 2~4개 추가 또는 B를 링크 한 줄로 실험.
- **유지:** 데이터는 부족하지만 보호 지표 정상 → 4주 연장.
- **No-go(중단):** 보호 지표 10% 이상 하락, 정책·애드센스 문제 발생, 또는 8주 누적 Playgama 수익이 의미 없는 수준(예: 지급 기준 100달러까지 1년 이상 예상) → 플래그 끄고 코드 제거.
- ※ 현재 사이트 방문이 적어 4주로는 표본이 모자랄 수 있다. 수치 기준은 표본 확보 후 다시 정한다.

## 9. 안전장치
- **기능 플래그 한 곳:** `assets/playgama-config.js`
  ```js
  window.PLAYGAMA = {
    enabled: false,          // 전체 끄기(kill switch)
    clid: '',                // 비어 있으면 아무것도 그리지 않음
    widgetId: '',            // 위젯을 쓸 때만
    homeEntry: true,         // 홈 카드 노출
    games: [                 // 큐레이션 목록 — gameURL은 대시보드에서 복사한 값 그대로
      // { slug:'...', gameURL:'...', thumb:'...', enabled:true, ko:{title,intro,howto,tips:[],for,mins} }
    ]
  };
  ```
  `enabled && clid` 둘 다 참일 때만 허브 목록·홈 카드가 그려진다. 꺼지면 허브는 "지금은 준비 중이에요 + 말로우 게임 바로가기"만 보여 준다.
- **게임 하나 즉시 제거:** 해당 항목 `enabled:false` 또는 삭제 → 배포 1회로 반영(약관 3.5 대응). 소개 문구도 같이 사라짐.
- **대체 UI:** iframe 삽입 후 N초(예: 12초) 안에 load가 오지 않거나 네트워크 오류면 "게임을 불러오지 못했어요. 다른 게임을 골라 보세요" + 다시 시도/닫기. (교차 출처라 '게임 삭제 페이지'를 정확히 판별할 수는 없음 — 아래 점검 스크립트로 보완)
- **정기 점검 스크립트:** `tools/playgama/check.mjs` — 설정의 `gameURL` 전체에 요청해 응답 코드·리다이렉트를 확인, 이상 항목을 출력(배포 전·주 1회 수동 실행).
- **설정 누락 방어:** clid가 들어간 문자열을 다른 파일에 하드코딩하지 않는다(정적 검사로 강제).
